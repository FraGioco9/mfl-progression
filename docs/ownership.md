# Source ownership after issue #708

Build with `npm --prefix site run build`. Validate with `npm --prefix site run check`.

- `site/modules/core-sources/shared-foundations.js` owns universal state, table/view configuration, constants, and DOM bindings; `site/modules/core-sources/shared-session.js` owns universal theme, Dapper opt-in/access policy, agent/account identity, account menu, and shell synchronization; `site/modules/core-sources/shared-routing.js` owns route/address parsing, canonical path construction, and the two navigation-transition identity declarations that lexically close that routing block; `site/modules/core-sources/shared-transitions.js` owns canonical page/view transition execution, stale-transition guards, route-loading coordination, mobile transition chrome, paint waits, and the published transition facades; `site/modules/core-sources/shared-page-lifecycle.js` owns page lifecycle from `resetPageScroll()` through Evaluation re-entry, eager Table/cross-route facades, and canonical `setPage()`; `site/modules/core-sources/shared-home-summary.js` owns Home status/count presentation, the cached Home summary readiness contract, and canonical bootstrap-summary loading from `updateStatusDate()` through `loadSummary()`; `site/modules/core-sources/shared-table-state.js` owns table page/view normalization, view-button/navigation link synchronization, sort-session identity/state, and default table-page state from `tablePageKey()` through `defaultTablePageState()`; `site/modules/core-sources/shared.js` now begins at `scheduleToastHide()` and owns toast presentation, wallet/watchlist/settings persistence, and later shared behavior. Home summary remains separate from table state, and table state remains separate from toast feedback, so bootstrap data loading and presentation feedback cannot become accidental dependencies of table navigation/session ownership. The canonical core manifest owns their order and validation must consume the complete Shared domain rather than any fragment in isolation when a contract spans boundaries. Validators that need Shared or the full canonical core should use `validate-core-sources.mjs` rather than duplicating physical fragment paths; generated-equivalence validators must compare `app-core-runtime.js` against the assembled Shared domain, not one physical fragment. Feature validators whose contract spans Shared foundations, session, routing, transitions, page lifecycle, Home summary, table state, and later shared behavior must likewise read the assembled Shared domain. A validator-local variable named `sharedCore` should represent assembled Shared unless that assertion intentionally validates one physical fragment boundary. Route/address assertions must not read `shared.js` directly for behavior owned by `shared-routing.js`; transition-specific assertions must not read `shared.js` directly for behavior owned by `shared-transitions.js`; page-lifecycle assertions must not read final `shared.js` directly for behavior owned by `shared-page-lifecycle.js`; Home-summary assertions must not read final `shared.js` directly for behavior owned by `shared-home-summary.js`; table navigation/view/sort-session assertions must not read final `shared.js` directly for behavior owned by `shared-table-state.js`. Mobile transition chrome, staged-transition loading, Home-summary entry, table-state/session behavior, Evaluation/Table facade, and similar cross-fragment behavior validators must consume assembled Shared through the canonical reader rather than maintaining their own physical source lists. Bootstrap/first-paint ownership validators that assert the live page/view transition handoff must likewise consume the combined canonical core rather than enumerating source fragments. Page-route gate validators that compare transition execution with later lifecycle/setPage behavior must use the combined canonical core because that contract intentionally spans `shared-transitions.js` and `shared-page-lifecycle.js`. Use assembled Shared for cross-boundary contracts and direct physical-fragment reads only for intentional ownership-boundary assertions. Evaluation table rendering, overall controls, render reuse and snapshot hydration belong to `evaluation.js`, loaded by the existing Evaluation route loader. The Shared domain keeps a 355,000-byte universal ceiling so route-specific behavior cannot silently return to code parsed by every route. Route/domain core sources intentionally have no hard byte ceilings: if they grow, split them when ownership, readability, or route cost warrants it rather than to satisfy an arbitrary number.
- `site/html-sources/manifest.json` orders the canonical HTML fragments. Edit the route's fragment or `first-paint.html`, never generated `site/index.html`. Fragment boundaries preserve inline script execution order and zero-request first paint. Release/config projections are applied by `normalizeIndexDocument`. The old duplicate Player-shell migration template has been removed from the core compiler.
- `site/responsive-sources/manifest.json` orders canonical responsive fragments by viewport/cascade stage and UI domain. `.css.inc` files are lexical fragments, not standalone stylesheets: media blocks can cross fragment boundaries. Assembly preserves the exact original cascade bytes. New rules belong at the corresponding existing cascade position. `responsive.css` is generated for validation/source composition; production loads it inside the one flattened `styles-runtime.css` bundle, with no extra responsive stylesheet request.
- `site/validation/responsive-*.mjs` owns the existing responsive contracts by UI domain. `validation/assertions.mjs` shares assertion mechanics; `validation-text.mjs` shares normalized cached file reads. The domain runners retain their existing gates and failure messages.
- `scripts/database`, `scripts/marketplace`, and `scripts/email` own operational Python packages. Run entry points from the repository root with `python -m scripts.database.rebuild_database_runner`, `python -m scripts.email.progression_email_preview`, etc. Database/report paths remain rooted at the checkout, not at the relocated module directory.
- `scripts/workflows/*.sh` owns extracted workflow implementation. YAML still owns triggers, permissions, credentials, environment, working directories and artifact boundaries. Database refresh executes helpers from its `builder` checkout, including when operating on the separately checked-out published site. Scripts are invoked with `bash`; no executable-bit dependency is required.
- `tests` owns Python and scheduler regressions. Run `python -m unittest discover -v -p 'test_*.py'` and `node --test tests/*.mjs` from the repository root. Workflow contract tests follow the actual script wired into each step. Additional tests execute local configuration helpers and syntax-check every extracted shell helper without sending email or contacting production.

See `docs/architecture-guardrails.md` for the current keep/relax/remove classification of repository-level constraints.

## Why the TypeScript alias remains

The installed canonical package is `typescript@7.0.2`. Importing it returns version metadata; `createSourceFile` is undefined. The binding validator requires `createSourceFile`, syntax-kind enums and AST predicates. The installed `@typescript/typescript6` package provides those APIs, and the generated-binding regression passes with it. Substituting TypeScript 7 therefore cannot provide equivalent behavior/diagnostics. Retain the alias until the canonical package exposes a compatible compiler API, then compare both validators before removing it.

Reproduce the capability check from `site`:

```sh
node --input-type=module -e 'const native = await import("typescript"); const legacy = (await import("@typescript/typescript6")).default; console.log({nativeVersion: native.version, nativeParser: typeof native.createSourceFile, legacyVersion: legacy.version, legacyParser: typeof legacy.createSourceFile});'
```

Generated runtime files, table-width runtime, deployment config projections, migrations and active dependencies remain tracked. These changes do not run a deployment.
